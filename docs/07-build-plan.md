# Toolr — Phase 2 Build Plan

Not part of the Phase 1 deliverable, but the natural next artifact: how the MVP gets built once this
architecture is approved. Six milestones, each ending in something demonstrable.

---

## Repository layout

```
toolr/
├─ app/                      expo-router routes (mirrors the nav tree in doc 03)
├─ src/
│  ├─ components/            primitives/ and domain/ (the inventory in doc 03 §3)
│  ├─ features/              auth/ tools/ search/ listing/ transactions/ chat/ profile/
│  ├─ lib/                   supabase.ts, queryClient.ts, analytics.ts, geo.ts, money.ts
│  ├─ schemas/               Zod — SHARED with Edge Functions, single source of truth
│  ├─ theme/                 tokens.ts (colour, type scale, spacing, radii)
│  ├─ i18n/                  index.ts + locales/en.json + locales/he.json
│  └─ types/                 database.types.ts (generated by the Supabase CLI)
├─ supabase/
│  ├─ migrations/            001_initial_schema.sql, 002_seed_dev.sql, …
│  └─ functions/             identify-tool/ interpret-query/ send-notification/
│                            match-tool-request/ delete-account/
├─ docs/                     this planning set
└─ e2e/                      Maestro flows
```

**Rules:** no file over ~250 lines; no component that both fetches and renders (hooks fetch, components
render); every user-visible string comes from `t()`; every money value is agorot until the moment it is
formatted.

## Milestone 1 — Foundation (build first, it makes everything after it boring)

Expo + TypeScript + expo-router skeleton · theme tokens · the primitive components · i18n with EN/HE and
RTL working from the first screen · Supabase project + migration 001 applied + generated types ·
the tab shell with placeholder screens.

**The whole identity ladder, because everything else sits on it:** anonymous session on first open ·
Google One Tap · email + password with confirmation and reset (which means custom SMTP configured on day
one — Supabase's built-in sender cannot deliver a reset) · Turnstile on anonymous sign-in ·
the sign-in *sheet* that returns the user to the action they were taking · Settings → Sign-in & security.

*Done when:* you can open the app as a guest, heart a tool, sign in with either method, and find the
heart still there — and the whole shell mirrors correctly in Hebrew RTL.

## Milestone 2 — Browse & search

Seed data (20 tools around Florentin) · `search_tools_nearby` wired to TanStack Query · list view ·
map view with clustering · filter sheet · tool detail · favourites · every empty/loading/error state ·
location permission with the rationale screen and the manual-area fallback.

*Done when:* an anonymous user can find the Bosch drill on a map and read its page, with no account.

## Milestone 3 — The 30-second listing

Camera → resize + EXIF strip → upload · `identify-tool` Edge Function with the confidence policy ·
the three confirmation variants · manual picker fallback · details screen · success screen.

*Done when:* **timed with a stopwatch, a non-technical person lists a real tool in under 60 seconds** —
and the flow still completes with the Gemini key deliberately broken.

## Milestone 4 — The transaction loop

Borrow request · accept/decline with push · transaction detail + status timeline · pickup screen with
the exact-location release · realtime chat with quick replies · return confirmation · two-sided ratings
with the double-blind publish rule.

*Done when:* two phones complete a full borrow end to end without anyone touching the database.

## Milestone 5 — Trust, safety and the rest

Profiles · report/block · damage reporting → disputes · notification preferences · settings · account
deletion (in-app + web) · tool requests + the nearby-owner broadcast · analytics events · Sentry.

*Done when:* the Play Data Safety form can be filled truthfully from what the app actually does.

## Milestone 6 — Ship

Privacy policy + ToS + safety guidelines · Play Console listing, screenshots, store copy in EN and HE ·
EAS production build · **closed testing with 12+ testers — start this early, the 14-day clock is the
usual launch blocker** · open testing in one neighbourhood.

## Test strategy

| Layer | What | Tool |
|---|---|---|
| Database | RLS policies — *especially* that no non-owner can read `tool_locations` and that a guest cannot insert a borrow request; the fuzz distance band; the search RPC's filters; guest upgrade preserving favourites | pgTAP / SQL assertions in CI |
| Schema | Migration applies cleanly to an empty database | CI job |
| Units | Money formatting, distance formatting/rounding, availability logic, AI response validation and the confidence policy | Vitest |
| Components | The primitives, in both LTR and RTL | React Native Testing Library |
| E2E | The three journeys that are the product: list a tool, find and request a tool, complete a return | Maestro |
| Manual | Every screen in Hebrew RTL at the largest system font size, on a mid-range device | Release checklist |

The RLS tests are not optional. They are the ones that stop a future migration from quietly publishing
everyone's home address.
